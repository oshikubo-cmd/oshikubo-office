# CAN-SLIM評価スキル（オニール式）

オニールのCAN-SLIMで**銘柄そのものの質**を測る。

> **役割分担を最初に確認する。**
> CAN-SLIMは「**この銘柄は買うに値するか**」を測る物差し。
> 「**いつ・どこで入るか**」は `agents/investor/knowledge/新高値ブレイク_判断軸.md`（DUKE。式）が担当し、
> 「**どこまで伸びるか**」は `目標株価とバリュエーション_上原式.md` が担当する。
> **CAN-SLIMで満点でも、ステージ2でなければエントリー対象外**。ここを混ぜない。

## 担当と成果物

- 担当エージェント: investor（`agents/investor/CLAUDE.md` を読んでから作業する）
- セッション開始時の必読（investorのCLAUDE.mdの手順に従う）
  1. `agents/investor/knowledge/自分のルール.md`
  2. `agents/investor/knowledge/新高値ブレイク_判断軸.md`
  3. `agents/investor/knowledge/サブ教材_個人投資家トーク.md` §1-9（**CAN-SLIMとビッグチェンジの一次整理がここにある**）
  4. `agents/investor/companies/<コード>_<社名>/README.md`（あれば）
- 成果物: 評価レポート1本
  - 単独依頼なら `workplace/projects/YYYYMMDD-<コード>-canslim/`

- 作業前にチケットを作成し、完了時に更新する（CLAUDE.mdのチケット運用に従う）

## Step 1: データを取る（IRバンクコネクタ）

**引数の形が関数ごとに違う。ここで毎回つまずくので、下の表のとおりに呼ぶ。**

| 取るもの | 関数 | 引数 | 注意 |
|---|---|---|---|
| 株価（日足） | `get_price_history` | `security_code`（**5桁**）, `from_date`, `to_date` | 4203→`42030`、285A→`285A0`。**取得は1年分が上限** |
| 週次信用残 | `get_weekly_margin_balance` | `security_code`（5桁） | 52週分。発行済株式数も一緒に返る |
| 年次業績 | `get_financials` | `edinet_codes`（**配列**）例 `["E00819"]` | `mode:"quarter"` を渡しても年次が返ることがある |
| ROE/PER/EPS/株数の推移 | `get_valuation_metrics_history` | `security_code`（5桁） | **このスキルの主力**。10年超のROE・PER・EPS調整後・発行済株式数が一括で returns |
| 大量保有報告 | `list_shareholders` | `edinet_code`（**単数形・文字列**） | 5%超の変動時のみ提出。全体像ではない |
| 開示一覧 | `list_disclosures` | `edinet_code`（単数）, `keyword` | 自己株式・経営陣・M&Aの裏取りに使う |
| セグメント | `list_segments` | `edinet_code` | 直近期の行が壊れて返ることがある（下記） |

### データの落とし穴（必ず読む）

- **`eps` は as-reported（分割未調整）。期をまたぐ比較には `eps_adjusted` を使う。**
  住友ベークライトの例では 2018/03 の `eps` 64.07 → 2019/03 320.51 と5倍に跳ねるが、これは株式併合であって成長ではない。
- **`shares_outstanding` も as-reported。** 分割をまたぐと不連続になるので、自分で倍率を掛けて基準を揃えてから増減を見る。
  （例: 2:1分割前の 49,590,478株 は分割後基準で 99,180,956株）
- **52週高値・安値は終値ではなく日中の高値・安値で計算する。** ここを間違えると判定が丸ごと狂う。
- **`list_segments` の直近期は、セグメント名が「平均臨時雇用人員)」のようなゴミで返ることがある。**
  壊れていたら決算短信・説明会資料の数字を使う。
- **IRバンクは個別銘柄のデータベースで、日経平均・TOPIXの指数データを持っていない。**
  → **Mは必ず別ソースで埋める**（Step 2のM参照）。

## Step 2: 7項目を判定する

各項目は **○（合格）／△（境界・一部合格）／✗（不合格）／取得できず** の4値で出す。
**「取得できず」を○や△で埋めない。**

### C — Current Quarterly Earnings（当期四半期利益）

| 基準 | 内容 |
|---|---|
| EPS | 直近四半期の前年同期比 **+25%以上**（理想は+40〜50%以上） |
| 売上高 | 同 **+25%以上** |
| 加速度 | **前四半期・通期より伸び率が上がっているか**（オニールが最も好む形） |

- EPSが取れない四半期は**純利益ベースで代用し、その旨を明記する**。自己株消却が進んでいる銘柄はEPS成長が純利益成長を上回る。
- **次の1〜2四半期の会社計画・アナリスト予想も見て、減速が見えているなら必ず書く。** 加速の最終局面で入るのが一番危ない。

### A — Annual Earnings（年間利益）

| 基準 | 内容 |
|---|---|
| 年間EPS成長 | **過去3年連続で+25%以上**（`eps_adjusted` を使う） |
| ROE | **17%以上** |

- **日本株ではROE17%は非常に厳しく、優良企業でも落ちる。** 落ちたことを隠さず書いたうえで、
  Step 3の「ビッグチェンジ」で補えるかを別途評価する。
- ROEは `roe`（報告値）を優先し、欠測期は `roe_computed` で埋める。**10年分を並べて体質を見る**
  （単年の良し悪しではなく、「この会社は構造的に何%の会社か」を出す）。

### N — New Product / Service / Management / Price High（新しさ）

以下のどれが当てはまるかを列挙する。**新高値だけで○にしない。**

- 新製品・新サービス・新技術
- 新市場・新用途（それまで売っていなかった先）
- M&A・新規事業
- **新経営陣**（`list_disclosures` で「代表取締役」「役員の異動」を検索する）
- **株価の新高値**（52週高値・上場来高値。日中ベースで）

### S — Supply and Demand（需給）

| 見るもの | 基準 |
|---|---|
| 発行済株式数 | 少ないほど良い。**減っているか**（自己株買い・消却） |
| 自己株式の消却 | `list_disclosures` に `keyword:"自己株式"` で開示を探し、**推測せず開示で裏を取る** |
| ブレイク時の出来高 | **50日平均の+40%以上**（理想は+100%以上＝2倍） |
| 信用買残 | 発行済に対する比率。1%超は重い。**週出来高比も併記する**（2つの物差しが割れたら発行済比を重く見る） |
| 売り手の存在 | 政策保有の解消、大株主の売却意向 |

`get_valuation_metrics_history` の `shares_outstanding` を分割調整して3〜5年の増減を出すこと。
**ここは見落とされやすく、発見が出やすい項目。**

### L — Leader or Laggard（リーダーか遅れ銘柄か）

- **事業のリーダー性**: シェア、セグメント構成比の変化（伸びている事業に寄っているか）
- **株価のリーダー性**: 年初来・1年・52週安値からの騰落率
- **RSレーティング（指数比）が出せないなら「未算出」と書く。** 自社の騰落率だけでRS80相当と言わない。

### I — Institutional Sponsorship（機関投資家の支持）

- `list_shareholders` で `holding_ratio` と `previous_ratio` を比較し、**増／減を1件ずつ**出す
- **大量保有報告書は5%超の変動時のみの提出なので、全体像ではない**ことを必ず注記する
- 証券会社のレーティング変更（新規カバー・格上げ）は新規スポンサーの兆候として加点材料

### M — Market Direction（市場の方向性）

**オニールが「投資効果の70%を決める」とする最重要項目。IRバンクでは埋まらない。**

別ソースで以下を確認する。埋められなければ **「取得できず」と明記し、評価は未完成だと宣言する。**

- 日経平均・TOPIXが200日線の上にあるか、200日線が上向きか
- フォロースルーデーが出ているか
- ディストリビューションデー（大口の売り抜け日）のカウント

## Step 3: ビッグチェンジで補正する

`knowledge/サブ教材_個人投資家トーク.md` §1-9 の整理では、
**最も重視するのはビッグチェンジ（マルチプル拡大）の有無**。日本株ではAのROE17%で落ちる銘柄が多いため、
**CAN-SLIMの点数だけで切らず、必ずこの5パターンに照らす。**

1. 成長の加速度の変化（新規事業の成功、値上げ、M&A、海外展開）
2. 事業リスクの低下（赤字→黒字転換、特定顧客依存の解消）
3. ストーリー・テーマ性の出現
4. ビジネスモデルの転換（フロー→ストック、卸→自社製造）
5. 株主還元の強化・ガバナンス改善（大幅増配、自社株買い、PBR1倍割れ対策）

そのうえで **マルチプル拡大がどこまで進んでいるか**を数字で出す。

```
過去5年平均PER（get_valuation_metrics_history の per_5y_avg）
現在PER（実績EPSベース）      ← これが5年平均を大きく超えていたら「初動ではない」
現在PER（今期予想EPSベース）
現在PER（来期予想EPSベース）
```

**実績ベースのPERが5年平均を大きく上回っていたら、「初動を取る取引」ではなく
「拡大の途中に乗る取引」であると明記する。** 外した時の下落幅がPERの戻り分だけ大きくなるため、
リスクの見積もりが変わる。

## Step 4: レポートを書く

構成は固定。結論を先に出す（`押久保.md` の「結論先出し」に準拠）。

1. **総合スコア表**（7項目の○△✗と、それぞれ1行の決め手）と「n勝n敗n保留」
2. **項目ごとの詳細**（C→A→N→S→L→I→Mの順。数値は必ず表で）
3. **ビッグチェンジ判定**（5パターンのどれに該当するか＋PER拡大の進捗）
4. **結論**: 典型的なCAN-SLIM銘柄か否か。乗る理由と見送る理由を**両方**書く
5. **未確認事項**（取得できなかった項目を残らず列挙）
6. **出典と取得日**

### 書き方のルール

- **「取得できず」を埋めない。** 特にMは埋まらないことが多い。埋まっていない評価は未完成だと宣言する
- **数値には必ず出典と取得日を付ける**（IRバンクコネクタ／決算短信／アナリストレポート）
- **「データが示す事実」と「解釈」を分ける。**
  例: 「発行済が3年で-11.0%」は事実、「需給は良好」は解釈
- **都合の悪いデータを省略しない。** 不合格項目こそ数値を厚く出す
- **投資助言・売買推奨はしない。** 「基準に照らすとこう」という形で示し、最終判断は押久保本人が行う
- 過去の自分のレポートと食い違う数字が出たら、**黙って直さずレポート内で訂正として明示する**

## よくある誤りチェック

作業の最後に、以下を自分で点検する。

- [ ] `eps` ではなく `eps_adjusted` で年間成長率を出したか
- [ ] `shares_outstanding` を分割調整してから増減を見たか
- [ ] 52週高値・安値を**日中ベース**で取ったか
- [ ] 自己株買い・消却を**開示で裏取り**したか（推測で書いていないか）
- [ ] 信用買残を**発行済比と週出来高比の両方**で出したか
- [ ] Mを埋められなかったなら、その旨を結論に書いたか
- [ ] ROEを単年ではなく**10年並べて**体質として見たか
- [ ] CAN-SLIMの結論を**エントリー判断にすり替えていないか**（それはDUKE。式の仕事）
