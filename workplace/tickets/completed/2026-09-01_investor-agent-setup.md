## 発生した問題と対処

1. **PDFからテキストが抽出できない** — DUKE。資料はスライド画像PDFで pdftotext が `Copyright (C) DUKE` 等の
   英数字しか返さない。加えてこの環境には poppler の pdftoppm が無く Read ツールのPDF直読みも失敗した。
   → PyMuPDF + Pillow でページをPNG化し、6スライド/枚のコンタクトシートにまとめて画像として読む方式で解決。

2. **ヒアドキュメントでの大容量ファイル作成が失敗** — Bash の heredoc が長文Markdownでパースエラーになった。
   → Write ツールに切り替えて解決。

3. **repo外の依存が想定より多かった** — 自動メモリ6本・定期タスク4本・MCPコネクタ2種・環境提供スキル4種が
   ファイルコピーでは移らないことが判明。→ README.md に「B. 再設定が必要なもの」として全項目を列挙した。

## 再利用可能な学び

- `[INSIGHT]` **スライド画像PDFの読み方**: pdftotext が効かず pdftoppm も無い環境では、PyMuPDF でページを
  PNG化 → Pillow で 3列×2行（1スライド880×660px）のコンタクトシート化 → Read で画像読み、が有効。
  この解像度で図中の注記まで判読できる。150ページ規模でも十数回のReadで済む。生成スクリプトは scratchpad に
  使い捨てで置けばよい。

- `[INSIGHT]` **トレンドテンプレート条件⑦には厳格版と緩い版がある**。ステージ動画[07]は「株価が50日線を
  上回っている」だが、テクニカル分析講座1[08]では「緩い基準では50日線の10%程度下でもOK」と補足される。
  判定レポートではどちらを採ったか明示が必要。既存の minervini-watch は厳格版で運用しており整合している。

- `[INSIGHT]` **DUKE。式のファンダメンタル3視点（収益性・持続性・確実性）は、オフィスCLAUDE.mdの部門経営の
  数値判断軸と完全に同一**。押久保の判断軸の共通基盤であり、投資と経営で別の枠組みを立てる必要がない。

- `[INSIGHT]` **「エージェントを作る」だけでは資料未参照の問題は解決しない**。参照先がPDFの山のままなら
  読まれない。一度だけ抽出作業をして「毎回読める分量」の1ファイルに圧縮し、それを必読に指定することが
  本質的な解決策。同種の課題（資料が重くて参照されない）には同じ型が使える。

- `[INSIGHT]` **仮置き前提のエージェント設計**: 移設予定がある領域は、①定義を1ディレクトリに閉じる
  ②共通ファイルへの追記は最小（1行）③絶対パスは1箇所に集約 ④repo外依存を列挙した移設手順書を同梱、
  の4点を守ると引っ越しがチェックリスト作業になる。
