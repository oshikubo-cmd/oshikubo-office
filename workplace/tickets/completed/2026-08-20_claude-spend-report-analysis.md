### 主な発見

- 22名 / 91日で 129,879リクエスト・入力161.6億トークン。従量換算 約$16,091（1人月$244相当）／実請求$0
- Cowork 42.0% + Claude Code 38.0% = 80%。エージェント型へ完全移行済み
- 上位3名で46.0%、上位10名で88.3%、下位6名で0.79%。利用格差が極端
- Chatのみ3名（m-matsuzaki / maeda / yukari.yokoyama）がエージェント未使用
- Opus はリクエスト32%でコスト55%。Haiku 4.5 はWeb検索の94.8%を担いコスト構成比1.1%
- キャッシュ読込率94.1%、キャッシュにより推定コスト77.5%削減

### 発生した問題と対処

- `net_spend` が全件0で「金額分析」が成立しない
  → 公開API価格による従量換算を代替指標として導入し、前提を明記して推定値と断って提示
- Fable 5 の単価が不明だったため `claude-api` スキルで公開価格を確認（$10 / $50）
- Bashヒートドキュメントで大きいHTMLを書こうとして `ENAMETOOLONG`
  → Writeツールに切り替えて解決

### 再利用可能な学び

- `[INSIGHT]` spend report CSVの `total_net_spend_usd` はシート課金契約では常に0になる。
  金額での評価を求められたら、トークン量 × 公開API価格で従量換算し「推定値」と明示して出す。
  この換算値はシート単価との比較材料になり、投資回収の議論に直接使える。
- `[INSIGHT]` spend report CSVには時系列カラムがない（期間合計のみ）。推移を見るには
  期間を分けて複数回エクスポートする必要がある。月次モニタリングの設計時に注意。
- `[INSIGHT]` Haikuの行はキャッシュ率が極端に低く（9%）Web検索回数が突出する。
  これは対話利用ではなくサブエージェント／検索実行役として動いている印。
  Haiku行を「利用の薄いモデル」と誤読しないこと。
- `[INSIGHT]` `data/scripts/analyze_claude_spend_report.py` は同形式のCSVなら
  そのまま再実行できる。`python data/scripts/analyze_claude_spend_report.py <csv>` でJSON出力。
- `[INSIGHT]` Bashヒアドキュメントで大きなファイル（20KB超）を書くと
  Windows環境で `ENAMETOOLONG: uv_spawn` になる。大きいファイルはWriteツールを使う。

### 2026-08-20 再修正（フレーミング）

押久保さんより「まだ試験運用なので評価する段階ではない」との指摘を受け、
数値は変更せずレポートの位置づけと打ち手を全面的に差し替えた。

- 冒頭に「試験運用フェーズ／個人の評価・査定には使用できない」を明示
- 評価ラベル（低活用・実質未使用）を状態ラベル（未定着・未着手）に変更、配色も緩和
- アクションから「投資回収判定」「継続/停止/再配置」を削除し、
  「成功パターンの型化と横展開」「試験運用の出口条件の設定」「シート配布の棚卸し」に差し替え
- 限界の最上位に「個人の評価・査定には使用できない」を追加

`[INSIGHT]` 利用ログ分析は対象組織のフェーズ（試験運用／本運用）を先に確認して設計する。
同じ数値でも「普及の進捗」と「個人の成績」では打ち手が正反対になる。

### 2026-08-20 請求データ反映（Version 5）

管理コンソールの請求書一覧を受領し、費用対効果を確定させた。

- **費用対効果 5.8倍**（実支出$2,773.75 vs 従量換算$16,091、実効割引82.8%）を結論1に格上げ
- 請求内訳テーブル（5月11名→8月20名）とシート付与方針のcalloutを§01に追加
- 利用者22名 > シート20名 ＝ 入れ替わりありと判明。「未使用シートが隠れている」懸念を解消
- 利用量順位は在籍期間の差を含むため、結論3・§07限界を「参加時期の差」の観点に修正
- アクションを現運用の継続前提に変更（範囲拡大より既存20名の定着、承認時の成果提出と実績の突合）
- 押久保さんの指示により、残高$0・自動チャージオフの利用抑制リスクは**反映しない**
- 8月の承認横ばいは設計どおりのため**問題として扱わない**

`[INSIGHT]` シート課金の費用対効果は「従量換算 ÷ 実支出」で算出できる。
spend report CSV と請求書一覧の2ソースを突き合わせるのが手順。
また段階付与している組織では、請求書のメンバー数推移が利用格差の解釈に必須。
