## 処理フロー

1. `state.json` を読み、24アカウント（鍵2件を除く）それぞれの `last_seen_id` を確認する
2. 各アカウントのプロフィール `https://x.com/<handle>` を巡回し、`browser-snippets.md` STEP 1 で
   本人ツイートのID一覧・投稿時刻・プレビュー本文を収集する（5アカウントずつ `browser_batch` でまとめる）
3. 鍵2アカウント（`hakureifarm` / `YoyogiCapital`）は毎回「非公開のまま」かだけ確認し、本文取得は試みない
4. アカウントごとに `last_seen_id` より大きいIDを新規分として抽出する。**投資・相場に無関係な雑談投稿も
   ここでは除外しない**（プレビュー本文だけでは投資関連かどうか判定しづらいため、いったん全件を候補にする）
5. 新規分すべてのIDを1本の配列にまとめ、`cdn.syndication.twimg.com` に移動して STEP 2 で全文を一括取得する
   （10件前後ずつに分割してよい）
6. 全文を読み、**投資・相場に関連する投稿だけ**を残す（銘柄名・銘柄コード・決算・マクロ指標・株価・
   四季報・IR・投資手法などに言及したもの。日常雑談・グルメ・趣味の投稿は除外）
7. アカウントごとに1〜3件（多いアカウントは重要度の高いものを優先）選び、Slack DM 用のダイジェストを組む
8. `state.json` の `last_seen_id` をアカウントごとに更新し、`log.md` に追記する

## DMのフォーマット

Slackの1メッセージは5,000字まで。26アカウント分を1本に収めるため、**ヒットしたアカウントのみ**見出しを立てる
（投稿がゼロ、または投資関連の投稿がゼロだったアカウントは末尾に「言及なし」として名前だけ列挙する）。

```
📊 *DUKE。参考26アカウント × 投資関連ポスト*（YYYY/MM/DD 朝）

*ヒットのあったアカウント（N件）*

*■ <表示名>（@<handle>）*
・<投稿本文の要約。1〜2行。数字・固有名詞は原文のまま> https://x.com/<handle>/status/<id>
・（同アカウント2件目があれば同様に、最大3件まで）

（ヒットしたアカウント分だけ繰り返す）

---
*投資関連の投稿なし*: <表示名>, <表示名>, ...
*鍵アカウント（スキップ）*: 五月(@hakureifarm), Yoyogi Capital(@YoyogiCapital)

🤖 毎日7時台に自動送信
```

- 見出しには必ず**実行日**を書く（アプリ起動待ちで翌日以降にずれることがあるため）
- 要約は原文にない情報を足さない。断定を強めたり弱めたりしない
- 投資助言はしない。「買い時」「仕込むべき」等の推奨表現は使わず、各アカウントが何を言っているかの報告に徹する
- 5,000字に収まらない場合は、各アカウントの要約を短くする（分割送信はしない）

## 既知の制約

### 1. 鍵アカウントが2件ある

チケットで判明していた `@hakureifarm` に加え、初期セットアップ時（2026-09-06）に `@YoyogiCapital` も
鍵アカウントと判明した。どちらもプロフィール上に「ポストは非公開です」と表示され、
syndication API 経由でも本文は取得できない。**巡回自体は毎回行うが、本文取得は試みずスキップする。**
将来フォロー承認されるなど状況が変わった場合は README・state.json を更新すること。

### 2. 未ログインでは直近5〜6件前後しか読めない

X のログイン壁により、プロフィールをスクロールしても表示されるのは直近5〜6件程度で頭打ちになる
（x-serenity-watch と同じ制約）。毎日1回のチェックでは投稿頻度が高いアカウント（テスタ・DAIBOUCHOUなど）
はギャップが出うる。取得できた最古のIDが `last_seen_id` より大きい場合は取りこぼしが発生しているので、
DM末尾に「⚠️ 一部取りこぼしの可能性あり」と明記する。

### 3. 投稿頻度・トピックの幅がアカウントごとに大きく異なる

- 井村俊哉・企業分析ハック・ふしちょうはベースライン時点で投稿が数週間〜2ヶ月止まっている
- sak・hiro_tyunは投資と無関係な雑談投稿が多い（フィルタで除外する）
- Made in Japanは英語投稿中心
- 上原＠投資家は判断軸ファイル（`agents/investor/knowledge/目標株価とバリュエーション_上原式.md`）の
  由来である「上原式」と同名だが、別人の可能性がある。内容を見て混同しないこと

### 4. 26アカウント分の巡回はコストが高い

1回の実行で最大26回のプロフィールnavigate + スクロールが発生する。`browser_batch` で5アカウントずつ
まとめて実行し、鍵2アカウントは本文取得ステップを省略することで負荷を抑えている。

### 5. 実行タイミング

スケジュールタスクは Claude Code アプリが起動している間に実行される。
アプリが閉じていた場合は次回起動時にまとめて実行される。DM見出しの日付は**実行日**であり、
データの収集期間はそれより前にずれることがある。
