## 構成（3ページ・H2×6・4,500〜5,000字）

### P1: 提案 AIリーダーが起こす変化

**H2-1: 号令する人から、自ら創る人へ。AIリーダーが起こす三つの変化**
- つかみ: 経営はAI活用の号令をかけるが、実装は現場任せ。この構図への問題提起
- 登壇者紹介: 2人とも経営の立場で自ら手を動かす実践者
- 野口氏のAIリーダー定義: 使いこなす→自ら作る→経営・事業部を巻き込む
- ［図版◎ zu01: スライド5「リーダーが自ら創ると、組織はこう変わる」］距離・速度・役割
- 木田氏: 伝言ゲームが消える。仮説を一瞬で形に。議論がモックから始まり意思決定が速くなる
- Tableau時代→今はサイトもアプリも自分で。1〜2ヵ月が1〜2時間に
- ［写真: id668_01 野口氏一人写り＋キャプション］

**H2-2: 資料の見た目は「正直どうでもいい」。仕事っぽかったことの無価値化**
- 「AIで資料を作るのは手抜き」問題 → 木田氏「どうでもいい」。生産性を上げるならいいものはどんどん採用
- ビジネスと技術の分断を繋ぐのがトランスレーター
- 野口氏: 仕様書・外注・レビューといった「仕事っぽかったこと」の無価値化。付加価値の本質が浮き彫りに
- 木田氏: パワポ職人卒業（数ヵ月パワポを触っていない）
- 野口氏: AIエージェントを組織の業務に恒久的に埋め込める段階へ
- ［写真: id668_02 木田氏一人写り＋キャプション］

### P2: 実践 積水ハウス イノベーション＆コミュニケーションの現場

**H2-3: 週末はClaude Code。教わったツールは半日で真似て、組織に展開する**
- 前提: 大企業グループの中の組織。セキュリティ・ガバナンスの制約の中でCMO/CDDO自らが手を動かす意味［図版○ zu02: スライド7「前提」］
- 木田氏のリアルな環境: 週末はClaude Code、会社ではCodex・ChatGPT・Google AI Studio
- 野口氏が新ツールを10分レクチャー→半日後には真似して組織展開。「CxOでナンバーワン」
- 環境づくり: ハードだけでなくソフト面（学習ループ）の仕掛け。野良AI対策は禁止ではなく広げる仕組み［図版○ zu03: スライド8「どんな環境で作っているか」］
- 研修: 画像生成でチラシ作成→「こんなことできたんだ」→学習サイクルが始まる
- モックの完成度にこだわらず、議論できる程度に速く。「考えてから作る」から「作りながら考える」へ［図版◎ zu04: スライド9「何が変わったか」］
- リーダーが自ら作ることで、部下が自由に発想できるカルチャー（心理的安全性）

**H2-4: 会社サイトもアプリも、まず自分でたたき台を作る**
- 事例1: イノコムの会社サイト。木田氏がたたき台モックを作成しイメージ共有→Web制作初心者の若手がClaude Code・Codexでさらに発展→制作パートナーと精度を上げ公開へ
- 展開: 各支店のPR・LP制作、チラシワークショップへ
- 事例2: ビジネストランスレーターアプリ（木田氏個人開発）。課題を入れると5Dフレームワークで整理。「鎌倉市の住宅展示場の来場者数を増やしたい」の例。作って見せると若手が真似する
- ［図版◎ zu05: スライド10「実際に作ったモック」］
- 野口氏: プロトタイプと本番の差がほぼない。「そのままデプロイしてよくないですか」。リードタイムほぼゼロ
- スピード実感: サイト制作は1〜2ヵ月もかからない。むしろ人のスケジュール調整が残る。「ボトルネックは人」

### P3: 今後 AI時代のリーダー像・リスク・メッセージ

**H2-5: トークンは資本。トップこそAIネイティブになるべき**
- リーダー像: 翻訳者から「動くモノに変換できる人」へ（ビジネストランスレーターの再定義）［図版◎ zu06: スライド12「リーダー像と実行のポイント」］
- キャリア論: 深く極めるより6〜7割の知識で越境。足りない部分はAIで補う。多様な経験の引き出しがAI時代の意思決定を速くする
- トークン傾斜: 上位層ほどトークン使用量を多く。意思決定・重要事項に紐づける
- トップのAIネイティブ化: 日本の大企業でトップがAIを使う会社は少ない。セミナーではなく体験。そばについて作ってもらう
- 理想: 社長が「これ作ったから使ってくれ」。DeNA・GMOなど経営トップ自らの例も

**H2-6: モデルは変わる前提で、「自社の型」と生ログを残す**
- リスク: ベンダー依存・地政学。モデルは変わる前提でやり続ける［図版◎ zu07: スライド13「リスクと備え」］
- 野口氏: AIレイヤーもマルチクラウド。データの正規化・整備。フロンティアモデルが使えなくてもローカルモデルで乗り越えられる状態に
- 木田氏: 自社の型（自社データ・業務ロジック・プロンプト）を資産として管理。モデルが変わっても品質を引き継げる
- 野口氏: エージェントとのやり取りは失敗も含め生ログで全部残す。後からスキル化・ハーネス化できる。「それが一番の備え」
- メッセージ: 野口氏=接触量の最大化＋ログ／木田氏=最初の仮説を自ら形にし共通言語に。個人で終わらせず組織知に
- 締め: 「とりあえず次の土日に作りましょう」（木田氏）。読者への補助線で着地［図版◎ zu08: スライド14「まとめ」］
