## 7. 次アクション候補（試験運用の次フェーズ向け）

### 優先度：高

1. **いまいる20名の中で使い込む人を増やす**
   費用対効果は実証済み（5.8倍）。範囲を広げる前に、既存参加者の定着を深めるほうが効く。
   成功パターンは**単一プロダクト特化型**（saiki＝Claude Code 97%／h-yamamoto＝Cowork 99%／
   ryo.tanizawa＝Cowork 99%）。この3名の使い方を**型として言語化し、承認時に提出された
   「出したい成果」と紐づけて渡す**のが最短。
2. **試験運用の「出口条件」を先に決める**
   現状は利用量しか測れていない。**何をもって本運用に移すと判断するのか**の基準
   （対象範囲・期間・判断指標）を決めておかないと、この先も同じ利用量レポートが並ぶだけになる。
   評価指標の設計は本運用移行の前提。

### 優先度：中

3. **承認時に提出された「出したい成果」と実績を突き合わせる**
   承認制では**事前に達成したい成果が提出されている**。利用量の多寡を見るより、
   **提出内容がどこまで実現できたか**を本人に確認するほうが、試験運用の評価材料として的確。
   使えていない場合も、原因（用途が合わない／やり方が分からない／時間がない）が分かれば
   次の打ち手が決まる。
4. **Chat中心の3名にエージェントを一度体験させる**
   m-matsuzaki / maeda / yukari.yokoyama は Chat のみ。特に m-matsuzaki は2,512件と
   **利用量自体は十分あり、使う意欲はある**。いまChatでやっている複数ステップの作業を
   1件Coworkに移す実演から始めるのが早い。
5. **Opus / Fable 5 の使い分けガイドを整備する**
   Opusがコストの55%、Fable 5が14.5%。シート課金下では即時のコスト削減効果はないが、

   目安を作る価値がある。Haikuをサブエージェントに使う現行パターンは維持を推奨。

   276リクエスト・4名でほぼ未活用。designer業務で使えるのか、Canva等の既存フローで足りるのかを

   集計スクリプトは再利用可能。毎月同じCSVを投入すれば同じレポートが出る。

## 8. 本レポートの限界

- **個人の評価・査定には使用できない。** 本データは試験運用期間の利用ログであり、
  業務内容・役割・繁忙度の違いを一切考慮していない。リクエスト数は**作業量でも成果でもない**。
  「使っていない」ことが低評価を意味する段階ではなく、
  **案内や支援が届いていないサインとして読むべきデータ**である。
- **日次・週次の推移が取れない**。CSVは期間合計のみで、時系列カラムがない。
  「使い始めたが離脱した」のか「最近使い始めた」のかを区別できない。
  推移を見るには期間を分けて複数回エクスポートする必要がある。
- **「22名」は利用実績のあった人数で、シート数ではない。** CSVには `total_requests` が0の行が
  1件も存在せず（最小値1）、期間内に1回以上使ったユーザーのみが記録されている。
  8/5請求のメンバーは20名なので、**期間中にシートの入れ替わりが起きている**（22名 > 20シート）。
  逆に言えば**完全未使用のシートが多数隠れている状況ではない**。
- **参加時期を考慮していない。** シートは5月11名→6月12名→7月以降20名と段階的に付与しており、
  **利用者の約半数は7月以降の参加**。§6の利用量順位は**在籍期間の差を大きく含む**。
  下位層が「使っていない」のではなく「まだ日が浅い」可能性が高く、順位をそのまま定着度として
  読むことはできない。正確に見るにはメンバーごとの参加日と突き合わせる必要がある。
- **金額は全て推定値**。実請求は$0。従量換算額は**利用規模を掴むための参考値**であり、
  費用対効果の判定には使えない。本運用移行時の規模試算の入力として使うのが適切。
- **リクエスト数は利用の深さを測れない**。1リクエストの価値（成果物の質・削減できた工数）は
  このデータからは分からない。下位ユーザーが「少ない回数で高価値な仕事をしている」可能性は
  否定できない。解釈にはヒアリングを併用すること。
- Sonnet 5 の導入価格（2026-08-31まで$2/$10）を反映していないため、推定額は上振れしている。
