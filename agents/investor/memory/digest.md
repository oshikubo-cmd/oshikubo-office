# Digest

## このエージェントは何のためにあるか

**要約**: 「新高値の分析を頼んでも、新高値ブレイクの資料を読まないまま提案が返ってくる」という
押久保の課題を、構造的に解消するために作られた。原因は資料本体（DUKE。資料）がPDF・動画資料として
storage に散在し、毎回全部読むのが物理的に不可能だったこと。エージェントを置いただけでは解決しない。

**解決の型**: コア講座資料（総論・ステージ・テクニカル講座1-4・下落相場対処・相場サイクル・
深掘り浅掘り・リスク管理）から判断軸を抽出し、**毎回読める分量**の1ファイルに圧縮した。
これをセッション開始時の必読に指定している。以後「資料を読んで」と指示する必要はない。

**読むべきもの**: `knowledge/自分のルール.md`（**押久保の実戦ルール。教材より優先**）→
`knowledge/新高値ブレイク_判断軸.md`（入口の基準）→
`knowledge/目標株価の算定_DUKE式と上原式.md`（目標株価の実務手順）→
`knowledge/目標株価とバリュエーション_上原式.md`（上値の物差し・象限マップ）→
`knowledge/参照資料マップ.md`（未収録領域を使うときの元資料の所在）。

## 分析は2段構え（2026-09-01 統合）

DUKE。式に、上原（元機関投資家）のEPS×PER目標株価の発想を統合した。
押久保の狙いは「Dukeはチャートで入るが、チャートがよくて割安ならさらにいい。初動を見つけるきっかけになる」。

| | 担当 | 何を決めるか |
|---|---|---|
| **DUKE。式** | タイミングの門番 | **いつ入るか**。ここは一切緩めない |
| **上原式** | 上値余地の物差し | **どこまで伸びるか／いつ降りるか** |

**足し算ではなく役割分担である。** 両者のエントリー思想は正面から逆（DUKE。=ステージ2のみ・
下げトレンドでは絶対買わない／上原=業績悪化＋バリュエーション低下からの回復初動で入る）。
素直に混ぜると「割安だから買う」になり、判断軸§9が禁じるステージ4の罠に落ちる。

**上原式の用途は3つだけ**: ①上値余地の選別（同じブレイクでも上値3倍と1.2倍を区別する）
②ウォッチリスト生成（割安×カタリストで候補を洗い、入るのはブレイクが出た時）③利確判断。

**接続点**: DUKE。「次の大化け株は下落相場の中で芽吹く。ウォッチリストに入れて監視する」と、
上原が割安圏で仕込む場所は同一地点。ここが押久保の探していた「初動のきっかけ」。
上原自身もモメンタム象限の入り方を「ファンダを伴う新高値ブレイクで入る」と定義しており、
**モメンタム象限に限れば両者は同じことを言っている。**

## 記録は3層に分ける（2026-09-01 確定）

投資日記（Googleドキュメント）＝時系列ログの正本。**リポジトリにコピーしない。**
`companies/` ＝銘柄ごとのカルテ。`knowledge/` ＝フレームワーク。

**Notionは導入しない。** 上原式の本質は「フレームワークをAIに渡す」「調べたことを蓄積する」の2点で、
このオフィスは既にその構造。足りていなかったのは企業データベースだけなので `companies/` を新設した。

⚠ **日記は教材PDFより優先度が高い場合がある。** 日記には後から出た訂正が入る。
実際にプルバックバイ ケース1の定義が訂正されており、判断軸ファイルを修正した。

**売買があったら日記エントリのドラフトを書く。** 押久保のフォーマットに、ステージ判定・
目標株価の前提・**最大の懸念事項**を足した形。懸念を買う前に書いておくと、後の答え合わせで
「懸念どおりだったのか、想定外だったのか」が切り分けられる。

## 押久保は既に自分のルールを持っている（教材より優先）

2026/08/14の南都銀行の振り返りで、エントリー方式と損切り幅を確定させている。
そして教材にない知見に到達している。

- ★**保ち合い終盤で出来高が枯れているか**が最重要。「ベースは時間をかけて株主を入れ替える装置。
  形がきれいでも出来高が枯れていないベースは信用できない」
- ★**「基準の通過」と「エントリー品質」は別物。** TT8/8合格でも見送りは成立する
- ★**損切りルール違反はポジションサイズの結果。** 再発防止はメンタルではなくサイズで行う

**分析でTT合格だけをもって銘柄を推さないこと。** ベースの質を必ず別途評価する。

繰り返している失敗パターン5件（①目標株価を算定せず1.5倍で済ませる ②買った後のファンダ調査を
実行しない ③同じ価格をサポートと判断して外す ④ルール違反が結果オーライで終わる ⑤待てずに飛び乗る）は
`fact.md` に記載。**①はエージェントが算定して解消できる。**

## 分析時に外してはいけない5点

1. **ステージ判定を先に置く。** 買い場はステージ2のみ。ステージ1・3・4なら「対象外」と明記する。
   ステージ4は割安に見えても買わない（もう一段下げる）
2. **トレンドテンプレートは合格数だけでなく不合格条件を出す。** 8条件のうち条件⑦は厳格版と
   緩い版（50日線の10%程度下でもOK）があるため、どちらで判定したか明示する
3. **52週高値・安値は日中高値・安値（分割調整込み）。** 終値ベースで計算すると判定が丸ごと狂う
4. **エントリーの話には必ずリスク側を添える。** 損切りライン（最大10%）・ポジションサイズ
   （試し玉＝総資金の1/25）・リスクリワード。片側だけ出さない
5. **印象評価をしない。** 「良さそう」「注目」は禁じ手。基準に照らした言い方だけを使う

加えて第2段では: **目標株価に必ず前提を添える**（予想営業利益/EPSをどう置いたか、倍率を何から取ったか）。
前提のない目標株価は数字遊びになる。上原の「損切りを％で決めない」方針は採用せず、
DUKE。の最大10%を外枠として必ず残す。

## 目標株価は2方式で出して突き合わせる（2026-09-01 追加）

DUKE。式の目標株価算定[23][24][25]を抽出し、上原式と並べた。実務手順は
`knowledge/目標株価の算定_DUKE式と上原式.md` §3-4。

```
DUKE。式（主）  時価総額 = 予想営業利益 × 営業利益倍率
上原式（検算）  株価     = 予想EPS × 適正PER
換算            PER ≒ 営業利益倍率 × 1.5   （法人税率33%前提）
```

- **DUKE。がPERでなく営業利益倍率を使うのは、EPSのノイズ（営業外損益・特別損益・税効果）を避けるため。**
  そして「時価総額で考え、株価では考えない。株価は全体の破片でしかない」
- **換算がズレたら、そこに情報がある。** 差の中身を特定するのが突き合わせの目的
- **DUKE。式は成長株専用。** 市況関連株・景気循環株・業績悪化中・赤字・債務超過には使わない。
  該当したら「算定対象外」と明記し、上原式の象限判定に切り替える
- **2方式の最大の共通点は「会社計画をそのまま信じない」こと。** 会社計画をそのまま使った時点で、
  どちらの方式で計算しても意味がなくなる
- DUKE。はDCF/DDMを明確に否定（割引率の感応度が高すぎる）。両者ともマーケットアプローチで一致
- **目標株価の数字そのものより、四半期ごとに算定して答え合わせを繰り返すことに価値がある**
  （DUKE。「自分のものさしで測るというルーティンを持つこと。それにより再現性のある投資ができる」）

## 立ち位置

投資助言・売買推奨はしない。判断材料の整理までが役割で、最終判断は押久保本人が行う
（DUKE。塾の「自調自考」と同じ原則）。発注・入金・出金も行わない。

## 運用上の前提

**仮置きである。** 押久保は新PC購入後、個人投資分析をプライベート環境へ移す意向。
そのため投資固有の定義はすべて `agents/investor/` に閉じ、オフィス共通ファイルへの追記は
エージェント一覧の1行のみに留めてある。storage への絶対パスは
`knowledge/参照資料マップ.md` の `STORAGE_ROOT` 1箇所だけ。移設手順は `README.md` に集約済み。

**ファイルコピーで移らないものが4つある**: 自動メモリ（投資系6本）、定期タスク（4本、全部投資系）、
MCPコネクタ（IRbank・Slack）、環境提供スキル（stage2-trend-template ほか）。詳細は fact.md。

## 再利用できる手法

**DUKE。資料の読み方**: PDFはスライド画像でテキスト抽出が効かず、この環境には pdftoppm も無い。
PyMuPDF + Pillow でページをPNG化 → 6スライド/枚のコンタクトシート化 → Read で画像として読む。
1スライド880×660pxで図中の注記まで判読できる。150ページ規模でも十数回のReadで済む。

**未抽出領域**: 目標株価の算定[23][24][25]・業績予想[27]〜[30]・PER[20]・決算シーズン[21]・
IR取材[31][32]・ボトム反転プロセス[14][15]。これらが必要なタスクでは元PDFに当たり、
読んだ内容は判断軸ファイルへ追記して育てる。
